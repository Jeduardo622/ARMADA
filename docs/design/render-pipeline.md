# Render Pipeline Decision Brief (W5 / Decision D3)

> **Status: Presented — awaiting the D3 human decision**
> (docs/design/art-direction.md §3.4). This brief is the evidence the
> decision was deferred for. It also fixes the Addressables policy and
> makes the perf budgets measurable.

## 1. The choice

Built-in render pipeline (current) vs **URP 14** (available for Unity
2022.3 via `com.unity.render-pipelines.universal`).

## 2. Evidence

**For URP:**
- The GDD's painterly water (pp. 16–17: hand-painted wave strokes,
  whitecaps, "artistic impression over photorealism") realistically
  means Shader Graph, which is SRP-only. On built-in it means
  hand-written HLSL — a specialist cost this team does not have.
- Mobile 30 fps mid-tier (D2-B): the SRP batcher and URP's
  mobile-tuned lighting are the modern path to the
  `docs/perf-budgets.md` draw-call budget; built-in receives no new
  optimization work from Unity.
- Built-in is legacy: no new features, and the asset-store shader
  ecosystem the art pass may lean on is URP-first now.
- **The conversion window is uniquely cheap right now.** The entire
  material inventory is: one generated board material
  (`LoadOrCreateBoardMaterial`, Standard shader), the primitive
  defaults the view provider creates in code, the flat-tinted bar/
  feature/wind materials (also code-created), and TMP — which ships
  URP-compatible shader variants in the already-committed essentials.
  Every one of these is regenerated by tooling (`RebuildAllGeneratedScenes`,
  the view provider, the capture stages). Post-art, the same conversion
  touches every imported material and re-opens every asset review.
- Both capture harnesses give the conversion a hard acceptance test:
  frames must re-baseline once and then hold determinism, and the
  before/after diff makes any rendering drift reviewable.

**For built-in:**
- Zero conversion work; the current flat-tinted look renders
  identically either way.
- One less package moving under the project during the art arc.
- Risk: the capture determinism contract (byte-stable ± 1-LSB) was
  proven on built-in; URP must re-prove it (expected to hold — same
  offscreen RT path — but unverified until the conversion slice runs).

## 3. Recommendation

**URP, converted now, in one bounded Class B slice** (pipeline asset +
renderer asset + graphics settings + shader swap in the code-created
materials + scene regeneration + both harnesses re-baselined with
determinism re-verified). Deciding built-in now means either giving up
the GDD's water or paying the conversion after art lands, when it is
strictly more expensive.

## 4. Addressables policy (fixed by this brief)

`com.unity.addressables` 1.22.3 is installed and
`AddressablesProfileSetup.cs` exists. Policy:
- **Art flows through Addressables**: ship-view prefabs, effect
  prefabs, UI skin atlases, and audio banks get Addressables groups
  (naming: `ships/`, `effects/`, `ui/`, `audio/` — W6 owns the full
  convention), enabling the GDD p. 24 remote-content path without app
  updates.
- **Scenes and code-created placeholder materials stay direct**: the
  generated scenes reference by path today and nothing pre-art needs
  remote delivery. The first Addressables consumer is the first
  prefab-backed `ShipViewProvider`.

## 5. Making the perf budgets measurable

`docs/perf-budgets.md` targets, and how each becomes a number instead
of a sentence (lands with the conversion slice; recorded here so the
budgets stop being aspirational):
- **Draw calls < 1.5k mid-fight**: the capture harness gains a stats
  line per frame (batches/setpass from Unity's rendering statistics)
  written into the capture manifest; the diff report flags budget
  breaches like a visual mismatch.
- **30 fps / p5 > 24 fps mid-tier**: not measurable headless on this
  workstation — requires the Android reference device; recorded as a
  device-matrix gate for the first on-device build (out of scope for
  this machine per the arc boundary).
- **< 800 MB runtime**: same device gate.
- **Texture budgets**: enforced by W6 import presets at import time,
  not at runtime.

## 6. Rollback

The conversion slice is one PR: revert restores built-in wholesale
(pipeline assets deleted, graphics settings revert, scenes regenerate,
harnesses re-baseline from the reverted code).
